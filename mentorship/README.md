# Mentorship

The teaching is one file: `JARVIS_MENTOR.md`. Read that before the notes. This folder is where a human teacher on video is studied. It is not a trading authority.

The trading mentor remains `doctrine/007_JARVIS_Momentum_Conservation_Trading_Mentor_Baseline.md`. Operating orders remain `JARVIS V1/STANDING_ORDERS.md`. A video does not change either file, does not change an S1–S4 act, and does not lift `SAFE_HOLD`.

## How a video gets in

Mark pastes the links in chat. Write each URL into `LINKS.md` with the date he sent it. Do not invent a link.

Reading uses the Transcriptor connector on Mark's user MCP settings (`transcriptor` → `https://transcriptor.gateway.mcpal.io/mcp`). That connector is not in the project `.cursor/mcp.json`, because this repository is public and the login session stays on his machine. If Transcriptor is not signed in, say so and wait. Do not scrape around it, and do not put an API key in this folder.

For each link, when Mark asks for the study:

1. Read the transcript and the chapters.
2. Pull a still frame only when the words depend on what is on the screen.
3. Write a proposed lesson in `JARVIS V1/JOURNAL.md`. Status stays proposed until Mark accepts it.
4. Append what the pass taught to `JARVIS V1/LEARNING_LOG.md`.

A lesson that contradicts the 007 baseline or the standing orders is a proposal, not a new order. Client tickets stay untouched. No new demo ticket comes from a video.
